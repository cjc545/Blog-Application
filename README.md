
# BlogApp (The Internet Is Not Dead)

This is a blog app created for my college class "Advanced Progamming & Web Development".

This app is written with ASP.NET (MVC), so C#, HTML and JS.

## Getting Started

To get this setup locally, you need to get the Microsoft SQL Database setup. To do this, follow these steps:

1. Ensure Microsoft SQL Server is installed on your machine 
2. Go to your cmd console, and type in the following:
> sqllocaldb create "BLOG-SERVER"
> 
> sqllocaldb start "BLOG-SERVER"
> 
N.B. The default name for the server is BLOG-SERVER, but if you want to define a different name, you'll need to update the string in appsettings.json

3. Go into the BlogApp project in VisualStudio, open the package manager console and type in the following:
> update-database

This will add the relevant tables to the DB server needed for this web app.

## Project Structure

This project follows a Model-view-controller architectural pattern, which divides this blog app into three interconnected components.
#### The Models manage the application's data and rules:
| Model			    | Model Variables														  | Description											|
| ----------------- | ----------------------------------------------------------------------- | --------------------------------------------------- |
| BlogPost          | Id, Title, Content, Published Date, Image File, UserId, User, Comments  | Models behaviour for blog list view				    |
| Comments          | Id, Content, Author, CreateAt, PostId, Post | Models behaviour		  | Models behaviour for posting comments of blog posts |
| ErrorViewModel    | RequestId, ShowRequestId											      | Model for displaying error messages					|
| LoginViewModel    | Email, Password														  | Model for user login								|
| RegisterViewModel | Name, Email, Password, ConfirmPassword								  | Model for user Registration							|
| User				| Id, Name, Email, PasswordHash, CreatedAt								  | Models users										|

#### The Views are responsible for presenting the data to the user:
| View			            | Description											|
| ------------------------- | ----------------------------------------------------- |
| Account/Login.cshtml		| Page for logging into account							|
| Account/Register.cshtml	| Page for registering a new account					|
| BlogPost/Create.cshtml	| Page for creating a new blog post 					|
| BlogPost/Delete.cshtml	| Page for deleting a selected blog post 				|
| BlogPost/Details.cshtml	| Page for viewing the details of a selected blog post 	|
| BlogPost/Edit.cshtml		| Page for editing a selected blog posts info 			|
| BlogPost/Index.cshtml		| Page for deleting a selected blog post 				|
| Home/Index.cshtml			| Page for deleting a selected blog post 				|
| Privacy/Index.cshtml		| Page for viewing privacy policy						|
| Shared/_Layout.cshtml		| This is a shared layout view for the navbar + footer 	|

N.B. All other views were generated by jquery or ASP.NET

#### The Controllers are responsivle for handling HTTP requests, processing user input, interacting with the model, and selecting the appropriate view to display:
| Controller		        | Description											|
| ------------------------- | ----------------------------------------------------- |
| AccountController			| Responsible for registering and logging in users, storing registered users in db									|
| BlogPostController		| Responsible for displaying posts, CRUD operations, and storing/deleting posts from db								|
| CommentsController		| Responsible for displaying comments view, and allowing users to comment on posts, storing in comments in db		|
| HomeController			| Responsible for displaying homepage, grabbing all posts and displaying small summary view							|
| ImageController			| Responsible for logic around uploading images to posts															|

## Authentication

Authentication is done manually; users can register for accounts, and use those accounts to login to the site and create posts. Passwords for registered acounts are hashed with SHA256 and stored in the database.

When a user logs in, the password is hashed, and the hash is compared to the db hash.  If they are both the same, the user logs in succesfully.

The are checks in place so only one account is given per email.
